# 状态系统

> 本文是状态（State）相关文档的入口：说明系统现在是什么、怎么配置、有哪些设计红线。
> 设计细节以 `docs/Agent/` 内各专题文档为准。

---

## 一、它替换什么

被替换的方案（针对 SillyTavern 生态的现状而言，非本仓库实现）：提示词要求模型在回复正文里输出特定格式标记（如 `<StatusPlaceholderImpl/>`），第三方扩展用正则从正文抓取、解析，再更新 HTML 状态栏；状态变量本身由**世界书条目**承载。四个问题：弱约束（格式靠"劝"）、正则脆弱、载体错了（世界书不是运行时数据结构）、无准入（所有 Agent 看到同一份状态）。

本系统的回答是六条支柱：

| # | 支柱 | 形态 |
| --- | --- | --- |
| 1 | 状态 = 后端一等数据 | `state/` 持久根，`state/document.json` 按楼版本发布，swipe 分叉独立 |
| 2 | 写入走工具 | `state.update`：schema 强约束、声明校验、批量报错回灌一轮改对 |
| 3 | 注入走推送（注入即准入） | 后端按 Profile / 条件算出切片并动态注入，**没注入的字段模型不知道存在** |
| 4 | 可见性按 Profile 配置 | `StateAccess` 三态（注入 / 可见 / 可写）逐字段逐 Profile |
| 5 | 脚本图灵完备 | 状态机层（数据驱动 + 比较器注册表 + 只能否决的脚本钩子） |
| 6 | 状态栏从数据接口读 | 面板读后端结构化结果，正则抓取方案废弃 |

**世界书的位置**：世界书**保持前端 JS 唯一实现**，不为状态服务，也不需要 per-Agent 门控。状态数据的宿主在后端，切片计算在后端，注入的**落位**由前端组装提示词时按既有机制完成——数据从后端来，位置由前端定。

## 二、功能组成

### 1 · 状态根与版本

- `state/` 是持久根：`state/document.json` 单文件随 run 原子发布，每楼一份聚合状态；`state/machine.json` 存机器位置，同根同机制（随楼发布、由下一楼继承）。
- 楼层绑定该楼产生的状态；重生成与删除取快照；swipe 分叉各自独立。
- 注入与面板都读**最新已提交版本**，同一版本，无第二个读取路径。

### 2 · 写入路径

- `state.update`：批量提交；**三态语义**——键未出现且不在 `remove` = 保持原值、`value` 为空 = 清空、出现在 `remove` = 删除，不允许用空值表示删除。
- 键的三种写法：字面 `环境/日期`、通配 `角色/*/着装`（`*` 一段、`**` 一层或更多）、正则逃生门 `/pattern/flags`；**没有宏**。
- 匹配是**归属判定**，一律编译成锚定全匹配（否则 `角色/*` 会顺带命中所有子字段）；机械归一只做全角→半角、反斜杠→斜杠、空白折叠；多候选报歧义，**禁止相似度猜测**。
- 声明存储在 `state-declarations/<name>.json`；保存时拒绝重叠条目与非法名字。
- `state.transition` 移动机器位置，其携带的字段写入在位置移动**之前**过声明校验与可写授权。

### 3 · 注入与准入

- `StateAccess` 三态逐字段逐 Profile，配置存在 Profile 上（`stateAccess`），Run 启动时冻结进 run 输入。
- **注入即准入**：按「注入」勾渲染 `键: 值` 文本并推送；未注入的字段模型既看不见也不会去更新。
- 落位由条目的 `injectSlot` / `injectDepth` 决定，默认 `atDepth` + 深度 4——**注入位置由变化频率决定，不由重要性决定**，为前缀缓存服务。
- 未配置访问的 Profile 得到零块：默认关，与"写入未配置即不约束"方向相反。

### 4 · 面板

- 面板是聊天之上的**浮层**：拖动标题移动、右下角缩放、点标题折叠、launcher 开关；几何（位置 / 大小 / 折叠 / 是否展开）是本地偏好，存在浏览器里，不写进声明。
- 面板上一个**「重新读取并重绘」按钮**：刷新会在重读状态值的同时重新解析当前绑定，所以刚在编辑器里改完声明、存完盘，按一下就生效，不必等下一次生成。
- 三层样式叠加，后一层只写与前一层不同的部分：
  - **Level 0 默认样式**：类名契约 `.tt-state-panel` / `.tt-state-panel__header` / `.tt-state-field`；
  - **Level 1 主题 CSS**：存于声明，编辑器**保存时**编译（解析、选择器加 `.tt-state-root` 前缀、按行列报错），编译产物才是存储内容；
  - **Level 2 HTML 模板**：存于声明，**保存时**编译成节点树。
- 模板写的是完整的 HTML：标签与属性不受限（SVG、`id`、`style`、`data-*`、事件都可用），只有"第二份文档或第二份脚本"被拒（`script` / `style` / `link` / `iframe` / `object` / `embed` / `template`）。绑定 `{{value 键}}` 可作文本或属性片段；`{{#if 键 op 值}}` 按比较分支；`{{#each 模式}}` 按匹配到的字段重复。绑定可以指向该聊天里**任何已声明字段**，不限于本面板 `match` 的范围。
- **值永远只是值**：模型写进状态的值只按文本或受限属性片段插入，不会变成标记。
- `on*` 处理器在页面内执行；从角色卡导入的面板若带处理器，安装前会问一次。
- 图片是**候选集 + 条件**（面板背景与字段值渲染为图两者都支持）：按声明顺序取第一个条件成立者，无条件候选为兜底且必须在最后；条件复用状态机层词汇表，可写条件脚本（共享模块表 `panels.scripts`）。
- 面板可见性与模型准入**无关**：`StateAccess` 管模型，面板是用户看自己的状态。
- **配了模板的面板没值也显示**：它显示的是作者画的那个形状。没有模板的面板仍按"有值才出现"——面板显示状态，不显示 schema。
- 最新一楼未更新状态时，面板标题栏显示"未更新"标记（后端写楼层 metadata `stateUpdated: false`，判据是状态文档是否变化）。

### 5 · 状态机

- **数据驱动**：代码里没有一个状态名、一条转移规则；`from` / `to` 都是数组（空 `from` 即无条件进入，多位置即并行区域），无数量上限。
- 条件走注册表（一张 map，未知 `op` 保存时报错并列出全部可用值），支持 `all` / `any` / `not` 组合；脚本钩子**只能否决**（`{ allow: false, reason }`），声明了钩子而没有引擎时报错。
- 推进两条路：模型用 `state.transition`（显式请求），Run 提交时自动求值（规则自触发）。**失败不带走已提交的正文**：错误记入 run journal 后继续提交。
- 可写授权只约束模型发起的写入；run 结束的自动求值**不**过它——那是用户配置的规则在行动。

### 6 · 谓词条目

- 回答"故事现在是不是这个状态"：内容只在状态成立时注入，**永不落盘**（只在组装提示词时由「状态 + 声明 + 条目定义」合成，无替换残留与索引残留）。
- **四阶段确定性求值**：收集候选 → 应用效果直到收敛 → 组内按优先级选一条（平局按声明顺序）→ 排序与预算（64 条上限，超限记 `over_budget` 而非静默丢弃）。
- 组是互斥的；**恒常条目不参与互斥**（常驻指令放 `constants`）；效果按标签作用——`inhibit` 在它成立期间排除带该标签的条目，`require` 让本条目等到其中之一被选中；效果引用的标签必须被某个条目声明，否则保存期拒绝。
- 每个被排除的条目都带原因（`unavailable` / `inhibited` / `requirement_missing` / `group_lost` / `over_budget`）——预览与组装期都解释自己。
- 注入落位 `atDepth` 4，键前缀 `tauritavern_state_predicate_` 独立于状态切片，随生成结束独立 flush。

### 7 · 绑定

三种资产（状态声明 / 状态机 / 谓词条目集）各自可绑定到**当前聊天**或**当前角色·群组**；绑定数据仍在既有的 `chat_metadata` / `power_user` 容器，界面只做选择。解析策略同一套：聊天 → 角色/群组 → 无 fallback，候选名字必须仍存在于已保存列表。

### 8 · Run 内上下文治理（工具记录脱壳）

- 单 Run 的 transcript 每轮全量重发，工具轮的协议壳随轮次复利稀释上下文。每轮 Model 请求前，`compact_tool_transcript` 把越过窗口的工具轮折叠为一条文本。
- 保留最近 `tools.unfoldedToolTurns` 轮原生格式（Profile 工具策略，默认 2，**下限 1**——折叠最新轮会留下无人应答的 tool call）；更早轮折叠，**读取结果正文一字不裁**；`state.update` 的旧参数只留键名（当前值在状态注入里）；折叠时丢弃该轮的 `Reasoning`。
- 变换纯函数、幂等（每轮最多折一个刚越线的新轮）；审计文件（`model-responses/`、`tool-args/`、`tool-results/`）不动；折叠发生时发 `tool_transcript_compacted` 事件。

### 9 · 编辑器

面板应用 5 个页签：Profiles、Runs、**State**（声明：字段表 / 面板 / 面板字段 / 图片候选集 / 共享脚本 / 主题 CSS / HTML 模板 / 访问配置）、**Machines**（状态机与求值预览）、**Predicates**（谓词条目集与求值预览）。每个编辑器：草稿本地持有、保存时归一、未保存改动有守卫、新建即预填默认名与可用示例（`scene-state` / `scene-flow` / `scene-tones`）、顶部常驻"这是什么"引导。

三个编辑器都能把一个文件读成一份资产，也都能写出一个文件：新建区的「导入」选一个文件就直接存下并打开（名字取自文件，不必先在名称框里打字），footer 的「导出」把当前草稿写成 `<名字>.scene.json` / `.machine.json` / `.predicates.json`。文件带 `kind` 与 `version`，所以别的文件会被拒绝而不是半读进来。共享脚本也能选一个 `.js` 文件导入（模块名取文件名），词表的「文件路径」有原生文件选择框（`plugin:dialog|open`，非桌面宿主时按钮说明该窗口没有选择器）。

三个编辑器各带一个**整份文档的 JSON 框**：表格旁边就是这份声明 / 状态机 / 条目集的全文。三百个字段是粘进去的，不是点出来的。框是草稿的视图——表格改动会重印它，框里的文字只有按「应用 JSON」才会生效，所以过期的粘贴不可能盖掉刚做的修改；粘坏了就地报错，草稿一字不动。

### 10 · 随卡携带

- 三类状态资产都能装在角色卡（或预设）里，各占一个扩展键：
  - `tauritavern.stateDeclarations` = `{ version, items: [{ scene }] }`，每个 `scene` 就是「导出场景」写出的那份文件（`kind` / `version` / `name` / `declaration`）—— 卡与 `.scene.json` 是同一个格式、同一个读取器；
  - `tauritavern.stateMachines` = `{ version, items: [{ name, machine }] }`；
  - `tauritavern.statePredicates` = `{ version, items: [{ name, set }] }`。
  后两者没有文件格式，名字本来就是存储键，所以 item 就是名字加文档本身；场景那份要包一层是因为 `.scene.json` 已经存在。
- 导入卡时：卡里的每份文档存进后端命名存储（同名且内容相同则跳过，内容不同才问一次是否覆盖），随后把该角色绑定到每一类里的第一份。绑定按**头像文件名**写入 `power_user.<kind>_bindings.characters[<avatar>]`。
- 卡片资产面板（角色卡/预设旁的「Agent 资产」）能查看、内嵌、移除这五类资产（配置 / Skill / 场景 / 状态机 / 条目集），并显示各自带了多少东西：场景报字段与面板数、是否含机器与条目，状态机报阶段与转移数、有无脚本钩子，条目集报组数与条目数。
- **默认卡自带示例**：`default_Seraphina.png` 出厂即携带 `seraphina-scene`（字段 / 面板 / 状态机 / 谓词条目各用了一遍），开聊即见状态栏。默认内容的安装本身只是文件拷贝，所以由 Agent 扩展在启动时做一次**版本化播种**：把示例声明写进命名存储、写进卡片扩展、并绑定到该头像，成功后记下 `defaultSceneSeedVersion`——用户删掉场景或解绑之后，它不会再回来。同名场景已存在且内容不同（用户自己的作品）时整个播种让路。

## 三、配置入口速查

| 要配置什么 | 去哪里 |
| --- | --- |
| 状态有哪些字段（键模式 + 显示名） | `State` 页签 · 声明字段表 |
| 面板长什么样（布局 / 主题 / 模板 / 图片） | `State` 页签 · 声明的面板区 |
| 哪些字段对某个 Profile 注入 / 可见 / 可写，注入位置 | `Profiles` 页签 · State Access |
| 机器怎么走（状态 / 转移 / 效果 / 钩子） | `Machines` 页签 |
| 条件成立才注入的内容 | `Predicates` 页签 |
| 资产绑定到哪个聊天或角色 | 各页签内的绑定区 |
| 单 Run 保留几轮原生工具格式 | `Profiles` 页签 · 运行策略 · `unfoldedToolTurns` |

## 四、设计红线

- **面板渲染期零解析**：模板与主题只在写入 / 保存时编译；渲染器只 `createElement` / `setAttribute` / `textContent`，并把 `on*` 绑成监听器。
- **值永不当标记**：渲染器从不由值生成标记，`{{raw …}}` 按名字拒绝；模板绑定必须命中声明里的某一个字段。
- **注入默认关**：未配置访问即零块注入；与"写入未配置即不约束"方向相反。
- **世界书前端唯一实现**：不为状态服务，不搬到后端。
- **谓词条目永不落盘**：求值结果只活在组装期。
- **恒常条目不参与互斥**：常驻指令不被组内竞争挤掉。
- **注入即准入**：不注入 = 不知道存在；准入是双向的。
- **面板可见性与模型准入解耦**：面板是用户看自己的状态，不按 Profile 裁剪。
- **失败不静默**：校验失败返回可恢复错误；状态允许落后于剧情，但不允许悄悄消失。
